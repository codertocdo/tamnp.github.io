It's not an exaggeration to say that graphs are the backbone of modern computing. ## 1. What is a Graph?

At its core, a **graph** $G = (V, E)$ is a mathematical structure consisting of two things:

* A non-empty set $V$ of **vertices** (also called nodes).
* A set $E$ of **edges**, where each edge connects a pair of vertices.

The number of vertices $|V|$ is called the **order** of the graph, and the number of edges $|E|$ is called the **size** of the graph.

Think of a graph like a city map: intersections are vertices, and roads are edges. The elegance is that this simple abstraction can model *anything* - friendship networks, neural pathways in the brain.

### Directed vs. Undirected Graph

The first major classification is by edge direction.

**Directed graph (digraph):** Each edge $e \in E$ is an *ordered* pair $(v_i, v_j)$, meaning it has a specific tail (start) and head (end). Think of one-way streets or Twitter "follow" relationships.

**Undirected graph:** Each edge $e \in E$ is an *unordered* pair $\{v_i, v_j\}$, meaning it's bidirectional. Think of Facebook friendships or two-way roads.

**Mixed graph:** Contains both directed and undirected edges - a hybrid that shows up in certain routing problems.

### Special Edge Types

Two additional edge concepts are critical to understand:

**Loop edge (self-loop):** An edge where both endpoints are the same vertex - i.e., $(v_i, v_i)$. Think of a webpage linking to itself.

**Parallel edge (multiple edges):** Two or more edges sharing the exact same pair of endpoints. A graph with parallel edges is called a *multigraph*.

### Adjacency Relations

For a graph $G = (V, E)$:

* Two vertices are **adjacent** if they are connected by an edge.
* Two edge are **adjacent** if they share a common vertex.
* A vertex and edge are **incident** if the vertex is an endpoint of the edge.

Three derived concepts follow naturally:

* **Independent vertex set:** A subset $V' \subset V$ where no two vertices are adjacent to each other.
* **Independent edge set (matching):** A subset $E' \subset E$ where no two edges share a vertex.
* **Clique:** A subset $V' \subset V$ where every pair of vertices is adjacent — a fully connected sub-group.

## 2. Vertex Degree: The Pulse of a Graph

The **degree** of a vertex $v$, written $\deg(v)$ or $d(v)$, is the number of edges incident to it. By convention, a loop counts twice.

* $\Delta(G)$: the **maximum degree** among all vertices in $G$
* $\delta(G)$: the **minimum degree** among all vertices in $G$

For **directed graphs**, we split degree into two components:

* **Out-degree** $d^+(v)$: number of edges leaving $v$.
* **In-degree** $d^-(v)$: number of edges entering $v$.

Two special vertex types deserve names:

* **Isolated vertex:** $\deg(v) = 0$ — completely disconnected, no neighbors.
* **Pendant vertex:** $\deg(v) = 1$ — only one connection; its single edge is called a **pendant edge**.


### The Handshaking Theorem

This is one of the most elegant results in all of graph theory:

> **Theorem 1.1 (Handshaking Theorem):** In any graph $G = (V, E)$,
>
> $$\sum_{v \in V} d(v) = 2|E|$$

**Intuition:** Every edge contributes exactly 1 to the degree of each its two endpoints, so every edge is counted twice when we sum all degrees. It's like a room full of people shaking hands - every handshake increments two people's handshake count by one.

**Corollary:** The number of odd-degree vertices in any graph is always even. This follows because the left-hand side $2|E|$ is always even, and the even-degree vertices already contribute an even total.

For directed graphs, a related identity holds:
 
$$\sum_{v \in V} d^+(v) = \sum_{v \in V} d^-(v) = |E|$$
 
Each edge contributes exactly once to the out-degree of its tail and once to the in-degree of its head.

### Graphical Sequences

A sequence of non-negative integers $\{d_1, d_2, \ldots, d_n\}$ is called **graphical** if there exists a simple graph whose vertex degrees match the sequence exactly. 

The **Erdős–Gallai theorem** gives the definitive test: a non-icreasing sequence $d_1 \geq d_2 \geq \cdots \geq d_n$ is graphical if and only if:

$$\sum_{i=1}^{k} d_i \leq k(k+1) + \sum_{j=k+1}^{n} \min(k, d_j) \quad \text{for all } k = 1, \ldots, n-1$$

## 3. A Zoo of Graph Types

My lecture notes cover a rich taxonomy of special graph forms, each with distinct properties and formulas worth memorizing.

### Simple Graph vs. Multigraph

**Simple graph:** No loops, no parallel edge. This is the "default" assumption in most algorithm discussions.

**Multigraph:** Allows loops and parallel edges. Adjacency matrices for multigraphs store counts rather than 0/1 bits.

### Null Graph

A graph where $E = \emptyset$ — vertices exist, but there are zero edges. Every vertex is isolated.

### Regular Graph ($k$-regular)

A **regular graph** is a simple graph where every vertex has the same degree $k$. We call it a **$k$-regular graph**.

> **Property:** A $k$-regular graph with $n$ vertices has exactly $\frac{nk}{2}$ edges.

### Complete Graph $K_n$

A **complete graph** $K_n$ is a simple graph on $n$ vertices where every pair of distinct vertices is connected by exactly one edge.

> **Property:** $K_n$ has $\dfrac{n(n-1)}{2}$ edges. This is also the *maximum* number of edges a simple graph on $n$ vertices can have.

Note that $K_n$ is $(n-1)$-regular.

### Bipartite Graph

A **bipartite graph** partitions the vertex set $V$ into two disjoint non-empty subsets $V_1$ and $V_2$ such that $V_1 \cup V_2 = V$ and $V_1 \cap V_2 = \emptyset$, with the constraint that every edge connects a vertex in $V_1$ to one in $V_2$ - no edge runs within the same partition.

Real-world analogy: a bipartite graph models a matching problem - students on one side, courses on the other, edges representing enrollment.

**Complete bipartite graph $K_{m,n}$:** Every vertex in $V_1$ (of size $m$) is connected to every vertex in $V_2$ (of size $n$). It has exactly $m \times n$ edges.

## 4. Relationships Between Graphs

### Subgraph, Spanning Subgraph, and Induced Subgraph

Given $G = (V, E)$ and $G' = (V', E')$:

* $G'$ is a **subgraph** of $G$ if $V' \subseteq V$ and $E' \subseteq E$. Written $G' \subseteq G$.
* $G'$ is a **spanning subgraph** if it is a subgraph *and* $V' = V$ (it spans all vertices, but may omit edges).
* $G'$ is an **induced subgraph** on $V'$ if it contains all edge of $G$ whose both endpoints belong to $V'$. In other words, it's *the most edges you could have* on that vertex subset.

### Graph Isomorphism

Two graphs $G = (V, E)$ and $G' = (V', E')$ are **isomorphic** if there exists a bijection $f: V \to V'$ that preserves edge connectivity - i.e., $(u, v) \in E$ if and only if $(f(u), f(v)) \in E'$. 

**Necessary conditions for isomorphism:** Two isomorphic graphs must have:
* Equal numbers of vertices.
* Equal numbers of edges.
* Corresponding vertices with equal degrees

## 5. Representing Graphs in Memory

How we store a graph directly determines the time and memory complexity of every algorithm we run on it. There are three main approaches.

### Adjacency Matrix

For a graph with $n$ vertices $\{v_1, v_2, \ldots, v_n\}$, the **adjacency matrix** is an $n \times n$ matrix $A$ where:

$$a_{ij} = \begin{cases} 1 & \text{if } (v_i, v_j) \in E \\ 0 & \text{otherwise} \end{cases}$$

For multigraphs, $a_{ij}$ stores the *number* of parallel edges between $v_i$ and $v_j$.

For **weighted graphs**, the matrix stores edge weights:

$$a_{ij} = \begin{cases} 0 & \text{if } i = j \\ L(v_i, v_j) & \text{if } (v_i, v_j) \in E \\ \infty & \text{if } (v_i, v_j) \notin E \end{cases}$$

**Key properties:**

* The adjacency matrix of an undirected graph is always symmetric ($A = A^T$).
* Checking whether edge $(v_i, v_j)$ exists is $O(1)$ — just look up $a_{ij}$.
* Space complexity: $O(n^2)$ regardless of the number of edges.
* There are $n!$ possible adjacency matrices for the same graph (one per vertex ordering).
  
```cpp
#define MAX_V 100

int adj[MAX_V][MAX_V];  // adj[i][j] = 1 if edge (i, j) exists
int n;                  // number of vertices

void init_graph(int num_vertices) {
  n = num_vertices;
  for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
      adj[i][j] = 0;
    }
  }
}

void add_edge(int u, int v) {
  adj[u][v] = 1;
  adj[v][u] = 1; // Remove this line for directed graphs
}

int has_edge(int u, int v) {
  return adj[u][v];
}
```

### Incidence Matrix

For a graph with $n$ vertices and $m$ edges, the **incidence matrix** is an $n \times m$ matrix $A$ where:

$$a_{ij} = \begin{cases} 1 & \text{if vertex } v_i \text{ is incident to edge } e_j \\ 0 & \text{otherwise} \end{cases}$$

This representation is less commonly used in code but appears often in theoretical analyses.

### Adjacency List

An **adjacency list** represents the graph as an array of $n$ lists, where the $i$-th list contains all neighbours of vertex $v_i$.

**Key properties:**
* Space complexity: $O(|V| + |E|)$ — far more memory-efficient for sparse graphs.
* Iterating over neighbors of a vertex $v$: $O(\deg(v))$.
* Checking whether edge $(u, v)$ exists: $O(\deg(u))$ in the worst case.

### Graph Density and The Representation Dilemma

The **graph density** $D$ of a simple graph $G = (V, E)$ is:

$$D = \frac{2|E|}{|V|(|V|-1)}$$

This ranges from 0 (null graph) to 1 (complete graph $K_n$).

* **Sparse graph** (low $D$): Use adjacency list. The matrix wastes $O(n^2)$ space mostly storing zeros.
* **Dense graph** (high $D$, approaching $K_n$): Use adjacency matrix. The $O(1)$ edge lookup pays off, and memory waste is minimal since most entries are non-zero.

| Representation   | Space      | Edge lookup  | Iterate neighbors |
| ---------------- | ---------- | ------------ | ----------------- |
| Adjacency matrix | $O(n^2)$   | $O(1)$       | $O(n)$            |
| Adjacency list   | $O(n + m)$ | $O(\deg(v))$ | $O(\deg(v))$      |

## 6. Walk, Paths, Cycles, Circuits

Before we traverse graphs, we need a precise vocabulary for *how* we move through them.

### Walk

A **walk** in $G$ is an alternating sequence of vertices and edges:

$$P = v_1 e_1 v_2 e_2 v_3 \cdots v_n$$

where each $e_i = (v_i, v_{i+1})$ or $(v_{i+1}, v_i)$.

* **Length** of a walk: the number of edges (equivalently, number of vertices minus 1).
* For simple graphs, a walk is often written just as a vertex sequece: $v_1 v_2 \cdots v_n$.
* A **simple walk:** no repeated edges.
* An **elementary walk:** no repeated vertices (implies no repeated edges).

Two walks can be concatenated: if $P_1$ ends at vertex $v_k$ and $P_2$ begins at $v_k$, then $P = P_1 \oplus P_2$ is also a valid walk.

### Path

In a **directed** graph, a **path** is a walk that respects edge directions - each step must follow the arrow. Notation: $P = v_1 \to v_2 \to \cdots \to v_n$.

In an undirected graph, walks and paths are equivalent.

### Cycle and Circuit

**Cycle** is a closed walk (start vertex = end vertex) in an undirected graph. Example: $v_1 v_2 \cdots v_k v_1$.

**Circuit** is a closed directed path in a directed graph - starts and ends at the same vertex, following edge directions.

## 7. Graph Traversal

Now we arrive at the operational heart of graph algorithms. **Graph traversal** means visiting every reachable vertex from a starting vertex $s$, visiting each vertex exactly once.

There are two canonical strategies, and understanding both is essential. 

### Depth-First Search (DFS)

Invented by Robert E. Tarjan in 1972, **DFS** dives as deep as possible along each branch before backtracking. It's the "explorer" approach - commit fully to one direction, retreat only when stuck.

```
procedure DFS(v):
  mark v as visited
  for each neighbour u of v:
    if u has not been visited:
      DFS(u)
```

Here is the C++ implementation:
```cpp
#include <iostream>
#define MAX_V 100

// Using adjacency list (Node struct from earlier)
struct Node* adj_list[MAX_V];
int visited[MAX_V];
int n;

void dfs(int v) {
  visited[v] = 1;
  std::cout << "Visited " << v << "\n";

  struct Node* curr = adj_list[v];
  while (curr != nullptr) {
    int u = curr->vertex;
    if (!visited[u]) {
      dfs(u);
    }
    curr = curr->next;
  }
}

void dfs_all() {
  for (int i = 0; i < n; i++) visited[i] = 0;
  for (int i = 0; i < n; i++) {
    if (!visited[i]) {
      dfs(i); // Handle disconnected components
    }
  }
}
```

### Breadth-First Search (BFS)

Proposed by E.F. Moore in 1959, **BFS** explores vertices **level by level** - first all immediate neighbours, then their neighbours, and so on. It's like ripples spreading outward from a stone dropped in water.

```
procedure BFS(v):
  queue ← {v}
  mark v as visited
  while queue is not empty:
    x ← dequeue from queue
    process x
    for each neighbour u of x:
      if u has not been visited and not in queue:
        mark u as visited
        enqueue u
```

We can also implement this algorithm with C++:

```cpp
#include <istream>
#define MAX_V 100

int queue[MAX_V];
int front, rear;
int visited[MAX_V];

void bfs(int start) {
  front = rear = 0;
  for (int i = 0; i < n; i++) visited[i] = 0;

  visited[start] = 1;
  queue[rear++] = start;

  while (front < rear) {
    int v = queue[front++];
    std::cout << "Visited " << v << "\n";

    struct Node* curr = adj_list[v];
    while (curr != nullptr) {
      int u = curr->vertex;
      if (!visited[u]) {
        visited[u] = 1;
        queue[rear++] = u;
      }
      curr = curr->next;
    }
  }
}
```

**Key application of BFS:**
* Finding shortest path in an **unweighted** graph (BFS always finds it in $O(V+E)$).
* "People You May Know" friend recommendations on social networks.
* Web crawlers that index pages level by level.
* GPS navigation for nearest-neighbor queries.

### Complexity Comparision

| Algorithm | Adjacency List     | Adjacency Matrix |
| --------- | ------------------ | ---------------- |
| DFS       | $O(\|V\| + \|E\|)$ | $O(\|V\|^2)$     |
| BFS       | $O(\|V\| + \|E\|)$ | $O(\|V\|^2)$     |

With an adjacency list, both algorithms are linear in the graph size. With an adjacency matrix, we pay $O(|V|^2)$ because scanning each row for neighbours costs $O(|V|)$ per vertex. This is the practical reason why adjacency lists dominate in algorithmic implementations.
